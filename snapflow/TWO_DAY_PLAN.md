# SnapFlow 两天完成清单（2026-09-14 版）

目标：今天跑通自己的一条真实日程，明天完成 10 张真实截图验收和可演示版本。
新版首页左下角有“两天上手清单”，可以逐步勾选、记录问题、导出验收记录。
网页地址：http://127.0.0.1:8765/guide.html

## 今天：照顺序做，不用写代码

1. 把这次新版 ZIP 解压到 `D:\CodeProgram\AgentM` 下的新目录。关闭旧启动窗口，再双击新版 `start-windows.cmd`。原有 `api_key.json` 留在 AgentM 目录。打开 http://127.0.0.1:8765 。新版左上角标记为 0914。
2. 点“打开相册”，选 2–3 张截图。查看事项摘要；点缩略图可看原图，只有需要修改才展开。缺少可选日期的任务也能保存；日程缺起止时间会留在“待核对”。先点一次“确认保存”。
3. 打开 https://open.feishu.cn/app 登录，创建自建应用。找到 App ID / App Secret；在权限管理开通**用户身份**的 `offline_access`、`calendar:calendar:read`、`calendar:calendar.event:create`。
4. 在应用安全设置，添加 SnapFlow“连接与使用说明”中显示的完整重定向地址；默认 `http://127.0.0.1:8765/api/feishu/callback`。发布版本，使应用可用范围包含你的账号。没有权限时需组织管理员协助，审批时间可能超过本日安排。
5. 在 SnapFlow“连接与使用说明”填 App ID / App Secret，保存配置，再登录飞书授权。返回后读取日历、选自己的可写日历、连接。Secret 只填本机页面，不要发到聊天中。
6. 保存一条自己的真实日程，点“同步已保存日程”。核对目标日历和勾选事项，再确认同步。打开飞书核对标题、起止时间、地点，设置并验证提醒。已同步成功的条目不能重复勾选。

今天完成的标志：你在飞书中实际看到一条从 SnapFlow 创建的、时间正确的日程；不是只看到“已配置”或“已连接”。

## 明天：用自己的真实资料验收

1. 准备 10 张最近的截图：4 张群通知、3 张作业/PPT、2 张活动海报、1 张普通图片。先人工写下应提取的事项，作为对照；隐私内容只选择自己愿意处理的范围。
2. 一次选入 10 张。从开始选图到确认完成计时，记录：总共多久、改了多少关键字段、漏了或误建多少事项。先记录原始结果，再修订，不要只记录改对之后的结果。
3. 检查刷新后修改是否保留、重启后记录是否存在、失败能否单独重试。飞书失败时先核对目标日历，再决定是否重试，不要重传整批截图。
4. 请 2–3 位同学独立体验，记录最卡的地方。当前是单用户本机应用，手机不能直接打开电脑的 127.0.0.1；手机真机和常驻后台提醒仍是后续工作。
5. 录一段选图、核对、保存、飞书中看到日程的视频，避开凭据页面。导出“两天上手清单”里的体验记录，列出最影响使用的 3 个问题。

## 遇到问题先这样处理

| 现象 | 先做什么 |
|---|---|
| 仍看到旧界面 | 关闭旧服务，只启动新目录；浏览器 Ctrl+F5 强制刷新 |
| Python 未找到 | 把完整错误文字发给开发端；不要反复打开不同版本 |
| 模型显示未配置 | 检查原有 api_key.json 是否在新版目录或其上一层，再重启 |
| 飞书提示回调不匹配 | 比对连接页完整地址，端口和 localhost / 127.0.0.1 必须一致 |
| 没有可写日历 | 核对用户权限、发布版本、账号可用范围；重新登录授权 |
| 日程显示待核对 | 只补原图缺少的关键时间；任务和收藏可以先保存 |
| 同步结果不确定 | 本地记录仍保留；先打开飞书检查，再只重试失败项 |

## 当前边界

- 新版已实现摘要确认、状态筛选、可选信息不阻塞保存、集中确认同步、目标日历保护、配置进度与指南。
- 开发端模型验证只在指定云主机执行；15 张新图包含 12 张虚构场景和 3 张公开网页截图，不能当成真实用户准确率。
- 飞书真实账号授权、Windows 本机运行与设备提醒仍需要你完成。代码中的模拟测试不是实际授权。
- 已有旧记录要迁移时：先关闭服务，复制整个旧 data 到尚未启动的新目录，核对文件数和大小，保留原副本；不要同时运行两个版本。

接口与权限依据：[飞书创建日程](https://open.feishu.cn/document/server-docs/calendar-v4/calendar-event/create)、[飞书官方 OAuth 实现](https://github.com/larksuite/lark-openapi-mcp/blob/main/src/auth/provider/oauth.ts)。
