# SnapFlow 连接自己的飞书账号

当前进度：用户已确认 Windows 新截图自动出现结果，以及首条飞书手动同步成功。已连接的用户无需重新配置，直接跳到第 4 节启用自动同步，并用新截图验收。任务和日程两类完整验收、时间核对、重复同步与重启恢复仍待完成。

## 1. 一次导入所需权限

在飞书开发者后台打开 SnapFlow 应用，进入 **开发配置 → 权限管理 → 批量导入/导出权限 → 导入**。

复制 [Feishu-Permissions.json](../deliverables/snapflow/Feishu-Permissions.json) 的完整内容，替换输入框中的示例，然后点击 **下一步，确认新增权限**，按页面提示确认申请。

四项权限均位于 `user` 中：

| 权限 | 当前用途 |
| --- | --- |
| `offline_access` | 获取刷新令牌，维持本人授权 |
| `calendar:calendar:read` | 列出本人可访问的日历，供选择可写入目标 |
| `calendar:calendar.event:create` | 在所选日历创建日程 |
| `task:task:write` | 创建本人任务、待办和作业 |

该清单与当前 `feishu.py` 发起 OAuth 时请求的范围一致。后台申请权限与用户登录授权是两个步骤；申请后还需发布生效并完成本人授权。

## 2. 在本机保存应用配置

个人配置已单独交付两个文件：`SnapFlow-Connect-Feishu.cmd` 和 `SnapFlow-feishu-private-config.json`。保持两者在同一个文件夹，只需双击最新收到的 CMD，即可自动将凭据保存到现有 SnapFlow，不需要打开 JSON 或再次填写密钥。助手会校验配套文件的 SHA-256 与 App ID；支持 Windows 接收同名文件时添加的后缀。

保存前先备份并验证旧飞书配置；相同凭据会保留已有登录和日历目标，不改动 Gemini 配置、截图或记录。窗口提供“复制所需权限”“复制回调地址”“打开飞书后台”和“打开 SnapFlow 设置”按钮。

**应用凭据验证成功不等于本人授权或同步成功。** 本次凭据验证返回 HTTP 200 / code 0；应用管理接口返回权限不足，当时未能代配置后台回调和发布；后续用户已完成连接并确认首条手动同步成功。助手从实际 SnapFlow 页面发起登录，保留浏览器绑定 Cookie。

真实凭据及个人化交付文件不入 Git，发布包不包含密钥；可复用源码为 `tools/windows_feishu_setup.py`，构建器为 `tools/build_windows_feishu_setup.py`。10 项隔离配置检查通过，原生配置窗口的执行细节尚未回收；用户已确认首条真实手动同步成功。

若没有配套私有配置，也可以手动配置：

飞书后台的 **凭证与基础信息** 页面提供 App ID 和 App Secret。在 SnapFlow 打开 **设置与连接 → 飞书与日程 → 应用提供者配置**，将两项分别填入，点击 **保存应用配置**。凭据直接填入本机应用，不发送到聊天或提交 GitHub。

## 3. 配置实际回调地址

在 SnapFlow 同一个配置区域复制 **当前回调地址**。到飞书后台 **安全设置 → 重定向 URL** 添加并保存。

必须使用 SnapFlow 显示的完整地址，包括当前端口和 `/api/feishu/callback`；启动时可能换端口，不能固定照抄 8765。若后续地址改变，应更新白名单后重新授权。

如果应用尚未启用网页能力，在应用能力区域添加/启用网页，并将本机 SnapFlow 首页地址填写为桌面端主页。当前应用只在 Windows 本机运行，移动端访问与公共部署尚不在本次验收范围。

## 4. 发布给自己使用

进入 **版本管理与发布**，创建一个版本，例如 `1.0.0`，说明填写“连接截图任务和日历”；将自己加入可用范围，再按后台提示发布。若要求管理员审核，须等待有权限的管理员批准，不能把已提交审核当作已发布。

## 5. 登录并选定目标

回到 SnapFlow 点击 **登录飞书并授权**，由本人完成飞书授权。

授权回来后，先点击 **选择飞书日历**，选中自己的可写日历并点击 **连接日历**；再点击 **连接我的飞书任务**。

首次验收先从已有记录中选择一条任务和一个日期明确的日程，分别点击同步，去飞书核对标题、日期时间和归属。成功后，再勾选希望自动同步的类型并点击 **确认同步授权**。自动同步授权仅对之后保存的事项生效，已有记录从详情单条同步。

若返回错误，保留页面提示并先核对飞书是否已经创建，再处理重试，避免重复记录。
