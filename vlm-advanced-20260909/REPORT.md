# VLM 图片理解实测：Gemini 3.5 / Qwen 3.7 / Doubao Seed 2.1 等

测试日期：2026-09-09，北京时间。使用用户 `api_key.json` 中配置的 Galbot 网关，不包含或公开密钥。全部运行于 00:09:19–00:15:09，共 69 次推理调用（另有模型列表查询）；56 次 HTTP 200、8 次拒图、5 次客户端超时。返回 usage 合计 90,959 token，超时请求可能仍在上游执行和计费，因此这不是完整账单或费用硬上限。

## 核心结论

1. **Gemini 3.5 Flash、Qwen 3.7 Plus、Doubao Seed 2.1 Turbo 的当前网关路由均能正确处理本轮四类图片任务。**
2. **Qwen 3.7 Max 和 Max-CC 当前不能经此 Chat Completions 路由处理图片。** 两者四项图文请求全部 HTTP 400，报 `Unexpected item type in content`；各自纯文本控制请求均返回 `API_OK`。这不是密钥失效，也不是整个 Qwen 3.7 系列都不支持视觉，而是当前路由/输入兼容性问题。暂用 `qwen3.7-plus` 或已通过测试的 `qwen3.8-max`。仅凭错误无法进一步确定是后端模型不支持图片还是网关转换错误；客户端改提示词不能解决这一层问题。
3. **Doubao Seed 2.1 Pro 默认设置明显较慢。** 照片与图表正确，但界面、双图任务均在约 55 秒时客户端读超时；不能把这两项判为“图片理解错误”。扩展超时和显式关闭思考的对照另列，不覆盖原始失败记录。
4. 本轮还验证了网关中的 Gemini 3.8 Flash、Qwen 3.8 Max、GPT-5.5 / 5.6 Sol、Claude Opus 5 / Sonnet 5、Kimi K3、MiniMax M3。它们在这四个基础/中等难度任务上均全部通过。**题目太少、通过率出现饱和，不能据此判定谁是行业最强 VLM。**

## 对照测试与豆包参数优化

### 1. 豆包 Pro 默认模式与快速模式

默认双图任务把 socket 超时从 55 秒延长到 120 秒后，**83.528 秒返回，7/7 正确**。这支持其默认模式主要问题是耗时，而不是已经证明不支持双图；并不能仅凭此次重试区分全部推理、排队和网络耗时。

随后保持图片、题目和发送预算不变，对 Pro 显式设置 `thinking: {"type":"disabled"}`，完整重测四项：

| 项目 | 默认模式 | 关闭思考 |
|---|---:|---:|
| 照片 | 7/7，26.252 s | 7/7，2.424 s |
| 图表 | 7/7，54.489 s | 7/7，3.228 s |
| 界面 | 55.097 s 超时，未评分 | **6/7，2.762 s** |
| 双图 | 首次 55.101 s 超时；重试 83.528 s，7/7 | 7/7，2.911 s |

快速模式 4/4 有效回答，**27/28（96.4%），完整耗时中位数 2.837 秒**。usage 中 `reasoning_tokens` 为 0。照片、图表和双图分别观测到约 10.8、16.9、28.7 倍缩短，但每种设置都只有单次样本、运行时段不同，不能当作稳定提速倍数或严格因果估计。

快速模式唯一错项：题目要求“显存至少 24GB 且 Ready 的最便宜实例”，正确是 **C39**；模型选择了更便宜但状态为 **Busy 的 A17**。它正确读出了价格、选中状态等其余字段，却漏了可用性约束。因此快速模式适合进一步验证简单照片描述、OCR 或常规提取；多条件决策不应仅凭本测试自动采用。默认模式的界面题没有成功答案，不能声称默认模式在此题一定更准。

原始记录分别保留于 `diagnostics/` 与 `doubao-fast/`。没有把优化后的成功结果替换主表超时记录；也没有在网关上修改全局配置。

### 2. 无图对照：结构化输出不等于有证据

对六个路由，原封不动发送图表问题，但移除全部图片。目的在于确认答案是否依赖图像，并检查缺失输入时的行为；**不把无图答题分数并入视觉正确率**。

| 路由 | 无图返回 | 解释 |
|---|---|---|
| `gemini-3.5-flash` | 编造数值，例如 Alpha Q2=60、全年=210；偶合 4/7 字段 | 有图为 65、250；无图不能信 |
| `qwen3.7-plus` | 编造数值，例如 Alpha Q2=180、全年=750；偶合 1/7 字段 | 有图全部正确，无图会猜 |
| `gpt-5.5` | 数值/季度字段为 null，季度数组为空 | 未编造具体读数；空数组仍不宜当作真实“没有” |
| `qwen3.8-max` | 55 秒超时 | 无最终答案，不评价幻觉 |
| `doubao-seed-2-1-pro` | 55 秒超时 | 无最终答案，不评价幻觉 |
| `doubao-seed-2-1-turbo` | 55 秒超时 | 无最终答案，不评价幻觉 |

无图提示词仍要求固定 JSON 类型/选项，没有显式放宽所有字段为 null；这可能诱导猜测。因此这些结果只描述本次输入缺失场景，不能概括模型整体幻觉率。有图/无图差异支持图片对回答有作用，但不排除公共照片熟悉度或网关内部处理等混杂因素。

生产提示词应写明：“若图片缺失、模糊或字段不可见，返回 null，并说明不确定性；禁止补全或猜测。”应用端还应强制检查图片实际存在并验证业务约束。调用器 CLI 要求至少一个 `--image`，不会像无图对照那样遗漏图片。

## 实际选用建议

- 按你指定的系列，先从 `gemini-3.5-flash`、`qwen3.7-plus` 和 `doubao-seed-2-1-turbo` 开始接入；它们在默认配置下都完成了全部图片任务。
- 如果优先追求简单图片任务的低延迟，可试 `doubao-seed-2-1-pro` 加 `--disable-thinking`；本轮最快，但有一个多条件筛选错误，不适合未经复核就驱动重要操作。复杂任务若保留默认思考，可以增大 `--timeout`，但这只避免客户端过早放弃，不会让模型本身更快。
- 当前要用 Qwen Max 级别路由读图，可选本轮通过的 `qwen3.8-max`，不要把请求盲目切到拒图的 `qwen3.7-max` / `qwen3.7-max-cc`。
- 对响应时间敏感，可把 `gpt-5.6-sol`、`gpt-5.5`、`qwen3.8-max` 作为进一步业务测试的候选；这只是本轮网关观测，不是原厂速度排名，也没有比较费用。
- 真实业务选型应再使用你自己的图片：例如中文密集截图、模糊照片、遮挡、复杂图表和细粒度空间关系。本轮英文合成文字和简单场景不足以评定这些能力。

## 网关身份和可复现性注意事项

`/v1/models` 返回 48 个别名。本次选择 14 个理解型候选；没有把 embedding、图像生成专用模型或所有相邻版本全部纳入。报告中的“较新”仅描述本账号网关候选，不承诺穷尽各厂商最新模型。

**网关错误信息明确含有跨模型、跨厂商 fallback 配置**，例如 Claude 路由可以回退到其他 Claude 或 Qwen。它证明存在回退机制，但不证明某个成功请求实际发生了回退。请求的 model 与返回 model 字段不能作为上游身份认证；要做原厂能力归因，需要网关管理员提供实际后端版本和每请求路由记录。本轮结论仅适用于这些网关路由。

Google 官方确认 Gemini 3.5 Flash 支持图片输入、文本输出；Qwen 官方视觉文档包含 Qwen 3.7 的图片传入示例。原厂文档不能替代网关实测，也不代表此密钥能直连原厂。[Google 模型说明](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash)、[Qwen 视觉文档](https://help.aliyun.com/zh/model-studio/vision)

调用器根据 OpenAI 官方文档区分了 GPT 的输出预算字段；其余模型使用此网关已验证的兼容结构，没有据此冒充为官方直连示例。[OpenAI Chat Completions 参数](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)

完整调用命令、Python 示例、HTTP 消息结构、多图方法和复现命令见同目录 `CALLING.md`。原始结果在 `main/`，补测在 `diagnostics/`，每条都保留最终答案、HTTP 状态、耗时、返回 model、usage 和字段评分；不保存模型隐藏思考正文。

调用器通过 6 个离线单元测试，覆盖 URL 检查、密钥脱敏、禁止重定向转发凭据、请求结构、评分和豆包显式参数。没有训练模型、安装依赖、修改原有虚拟环境或更改用户密钥文件。
