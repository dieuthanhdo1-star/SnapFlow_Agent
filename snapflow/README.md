# SnapFlow Windows 截图助手

授权一个截图文件夹后，自动读取新截图、识别、分类并保存；内容不完整的事项留在“待核对”。可连接飞书任务和日历，或导出日程的 .ics 文件。原图不会被移动或删除。

## 打开和使用

1. 将整个新版文件夹解压到 `D:\CodeProgram\AgentM` 下，不覆盖旧版。先关闭旧版的后台终端。新版会自动选择可用端口。
2. 双击 `start-windows.cmd`。它会使用已安装的 Python 3.10+ 启动本机服务并打开页面。无需安装 Python 第三方依赖；若电脑还没有 Python，需先安装 Python。
3. 点击“授权截图文件夹”，页面内直接选择磁盘，再进入截图文件夹，点击“授权并开始”，无需等待外部 Windows 窗口。也可直接填写完整路径。默认也整理已有截图，可取消该选项。

以后把新截图保存到这个文件夹即可；修改后的截图也会重新检查并处理，相同内容仍会去重。扫描间隔约 3 秒，会等待文件写入稳定；只读这一层文件夹，不读取子文件夹。支持 PNG、JPG、WebP，每张最多 8 MB。相同图片不重复识别；错误结果可手动重试。也可以一次手动选择最多 30 张图片。

关闭浏览器后，最小化的 Python 后台窗口仍继续整理。关闭该后台窗口、退出登录、关机或电脑休眠时无法继续运行；重新双击启动程序后，会恢复已授权文件夹的扫描。已中断的模型请求不会自动重试。

“暂停”停止自动读取和自动保存；“撤销授权”忘记文件夹位置。已经发出的网络请求无法收回，其结果会保留为待核对，不再自动归档或同步。已有记录和原图均保留。显式手动上传、重试和确认事项是独立操作。

## 六种处理能力

| 分类 | 自动整理内容 | 连接去向 |
|---|---|---|
| 任务 | 工作和项目要求、执行步骤 | 本地 / 飞书任务 |
| 待办 | 缴费、取件、预约等生活事项 | 本地 / 飞书任务 |
| 作业 | 课程、提交要求、原文步骤、明确截止时间 | 本地 / 飞书任务 |
| 日程 | 活动时间、地点、原始通知 | 本地 / 飞书日历 / .ics |
| 灵感 | 设计、创意、有趣内容 | 本地归档 |
| 资料 | 教程、知识、参考信息 | 本地归档 |

缺年份、缺关键时间或无法判断的截图会留待核对，不猜日期。普通任务没有截止要求时可直接保存。每张聊天截图可拆出多个事项。截图里的指令和链接作为资料读取，不会自动打开或执行。

点击结果即可查看原图、编辑、标记完成或已读。飞书连接是**单向创建**；本地编辑、标记完成不会回写飞书。需要双端一致时，请在飞书同步修改。本地编辑后会显示提醒。

## 识别服务（产品提供者准备一次）

自动读取程序目录、上一级及同一项目旧版本中的识别配置，支持 ZIP 多套一层目录。现有网关默认路由仍为 `gemini-3.8-flash`，已设置的模型不会因升级重置。成功读取后，在项目的 `.snapflow-config/` 保留私有配置，后续换版本继续复用；请勿删除该目录，也不要对外分享。若 Windows 电脑从未收到密钥文件，需要将原来的 `api_key.json` 放在程序目录或项目目录后重启。交付包不包含真实密钥。

如果没有现有配置，在“设置与连接 → 识别服务”填写兼容图片输入的 Chat Completions API 地址、密钥和模型名称。凭据存于本机 `data/vision-private.json`，不会显示在首页或接口响应中。也可使用 `.env.example` 的环境变量方式。

**发行 ZIP 不携带真实密钥。** 本版仍是使用者本机运行的单用户程序，尚无面向公众的托管登录和计费服务。每天默认最多接收 100 张新截图，可在设置调至 1～1000；显式重试会额外调用模型。人民币费用由网关计费决定，应用没有可靠实时金额接口。

## 飞书（日历和任务）

产品提供者先在飞书开放平台准备应用，开启相应权限并发布可用版本：

- `offline_access`
- `calendar:calendar:read`
- `calendar:calendar.event:create`
- `task:task:write`

OAuth 回调地址以“设置与连接 → 应用提供者配置”中显示的地址为准，需要加入飞书开放平台的应用回调配置；默认是 `http://127.0.0.1:8765/api/feishu/callback`，系统限制导致端口变化时可能改用 18765 等端口。在设置下方“应用提供者配置”保存 App ID 和 App Secret；不要把凭据发送到聊天或随发行包公开。

使用者点击“登录飞书并授权”，选择可写日历，并连接“我的飞书任务”。如需自动同步，勾选相应选项后点击“确认同步授权”。授权仅对之后保存的事项生效；旧记录可从详情单条同步。

自动同步绑定当时选定的日历及任务账号；账号或日历变化会停止自动同步，需要重新确认。同步失败不自动重试，结果不确定时应先在飞书核对。任务只分配给当前授权账号，不给群聊或其他人发送消息。

应用配置和真实账号 OAuth 必须由有权限的人完成。代码和模拟接口检查不代表已接通真实飞书。飞书租户管理员也可能需要批准应用或权限。

接口依据：[飞书官方任务 SDK](https://github.com/larksuite/oapi-sdk-python/tree/v2_main/lark_oapi/api/task/v2)、[创建日程](https://open.feishu.cn/document/server-docs/calendar-v4/calendar-event/create)、[获取用户信息](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get)

## 数据与更新

所有整理结果、图片副本、授权和连接保存在本版 `data/` 中，属于私人数据，不要公开分享此目录。原来的相册文件不会被改动。

旧版本数据不会自动覆盖或删除。需要迁移时，先关闭两个版本并备份旧版 `data/`，再把它复制到**尚无 data 的新版目录**；新版首次启动会做兼容迁移。已有数据不要直接互相覆盖。本次源码改造前的开发副本也已归档。

请以启动窗口输出并自动打开的地址为准，不要一直刷新旧的 8765 页面。同一版本目录会记住上次成功的端口。仅供本机访问，不要将端口公开到互联网。

## 2026-09-14 启动诊断修正

启动窗口现在始终显示检查结果，并停留供查看。后台输出写到程序上一级 `tmp/snapflow-runtime/startup-*.log`；启动器会绕过代理检查回环地址，确认首页、脚本、样式能读取后才打开浏览器。此改动提供诊断，不代表已确认某台电脑白屏的具体原因。

如果首页仍空白，请先看启动窗口是否显示“服务和首页文件检查通过”，再提供地址栏完整地址及窗口中的错误文字。启动日志留在本机，不会自动上传。页面脚本或 API 出错时会持续显示提示，不再只短暂弹出消息。

## WinError 10013 自动换端口修正

用户日志已确认：后台在 `bind(127.0.0.1,8765)` 时被 Windows 拒绝。新版启动器先检查端口，并在实际服务器绑定失败时再次尝试 18765、18766、18767 和系统分配端口；浏览器使用后台报告的实际地址。所有尝试只监听本机回环地址。未知类型的错误不会被吞掉，全部端口被拒绝时仍会显示错误。

系统保留端口是可能原因之一，尚未检查该 Windows 电脑的端口保留清单。微软资料：[10013 与排除端口](https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/error-10013-wsaeacces-is-returned)。本次没有修改 Windows 防火墙、端口保留规则或要求管理员运行。已在开发端模拟 10013 并验证真实占用端口后的地址传递；最终仍需目标 Windows 打开确认。

## 文件夹按钮修正

点击按钮先打开页面内的选择面板，不再等待识别服务配置或原生 Windows 窗口。初始后台配置请求失败时也会保留按钮响应，并在页面显示错误。原生窗口没有出现时，可直接输入完整文件夹路径。路径通过同源、CSRF 保护的接口验证，只在明确授权后绑定；相对路径、不存在的目录、普通文件都不会被当作截图文件夹。

未连接识别服务时允许保存文件夹授权，扫描器等待服务可用后才读取图片并识别，不会提前把图片标记成失败。若选择不处理已有图片，授权时会记录已有文件的名称和修改信息作为排除基线。

本次通过 84 项后端/启动检查和 11 组 Chrome 离线交互，其中包含直接填写路径、缺少识别服务、初始配置请求失败后按钮仍可打开面板。Windows 原生对话框仍未实机验证；新增入口可绕过对话框，不代表已确认该电脑原生弹窗失败的具体原因。
